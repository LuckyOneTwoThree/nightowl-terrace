## 一、P0 · 安全漏洞（立即修）

### P0-1：syncScores manual 分支无鉴权 —— 任意用户可篡改比分操纵榜单
**位置**：[syncScores/index.js L120-132](file:///cloudfunctions/syncScores/index.js#L120-L132)

`event.manual` 分支直接写 fixtures 的 `st/sc` 并联动 settleMatches。云函数绕过集合权限，任何用户调用 `wx.cloud.callFunction({name:'syncScores', data:{manual:{id:'PL-1-ARS-COV', score:'0-9'}}})` 即可篡改任意场次比分 → 操纵 standings 总榜、污染周报。

**方案**：
```javascript
const ADMIN_OPENIDS = ['<你的OPENID>']; // 开发者工具「云开发→用户管理」或 seal 调试日志获取
exports.main = async (event) => {
  // manual 分支仅管理员可用（ESPN 自动分支为定时触发无 openid，不受限）
  if (event && event.manual) {
    const wxCtx = cloud.getWXContext();
    if (!wxCtx.OPENID || !ADMIN_OPENIDS.includes(wxCtx.OPENID)) {
      return { ok: false, error: 'forbidden: admin only' };
    }
    // ...原有 manual 逻辑
  }
```
部署后用一次「云端测试」传 manual 验证返回 forbidden。

### P0-2：seal checkin/boast 不校验场次 —— 夜猫榜/法庭可刷
**位置**：[seal/index.js L76-88（checkin）/ L91+（boast）](file:///cloudfunctions/seal/index.js#L76-L88)

checkin 仅查 `(uid,m)` 重复，不校验 m 是否存在于 fixtures、是否已开球。用户可对未来 1191 场批量打卡刷爆 hours 霸榜；boast 同理可对不存在场次立据。

**方案**（与 prediction 分支同款校验下沉为公共函数）：
```javascript
async function fixtureKickTs(db, mId) { // 返回 {ok, kickTs, fix} 
  const fix = await db.collection('fixtures').where({ id: mId }).limit(1).get();
  if (!fix.data.length) return { ok: false, reason: 'match not found' };
  const kt = bjTs(fix.data[0].t);
  return { ok: true, kickTs: kt, fix: fix.data[0] };
}
// checkin：场次必须存在；未开球可打卡（赛前立 flag 语义），已过开球后 36h 内仍可补打，
// 超窗拒绝（挡住遍历历史场次刷榜）
const fk = await fixtureKickTs(db, c.m);
if (!fk.ok) return { ok: false, error: 'match not found' };
if (!isNaN(fk.kickTs) && (now < fk.kickTs - 6 * 3600000 || now > fk.kickTs + 36 * 3600000)) {
  return { ok: false, error: 'checkin window: kickoff ±(-6h, +36h)' };
}
```
（开球前 6h 起可打、开球后 36h 内可补——覆盖「赛前立 flag」与「看完补打」两种产品语义，同时封死批量刷历史/未来场次。若你想要更严的「看完才能打」，把下界改成 `fk.kickTs` 即可。）

## 二、P1 · 逻辑缺陷

### P1-3：封存三态 `rejected` 全部未消费（防作弊链最后一公里）
**位置**：[predict.js L219-227 / L265](file:///miniprogram/pages/predict/predict.js#L219-L227)、[detail.js L163-171](file:///miniprogram/pages/detail/detail.js#L163-L171)、play.js onPick

cloud.js 的 callSeal 三态契约（true/seal 成功、'rejected'/业务拒绝、false/断网降级）设计完善，但三个页面入口全部 fire-and-forget：seal 以「开球已过」拒绝后，本地 storage 照存、toast 照弹「封存成功」——本地判据 `p.ts > kickTs+60s` 依赖设备时钟，**回拨时钟即可开球后封存并在 records/me/分享战报计分**。

**方案**（三处同款，约 30 行）：
```javascript
cloud.addPrediction({...}).then(function (sealed) {
  if (sealed === 'rejected') {
    // 云端明确拒绝（开球后/哈希不符）：回滚本地封存，如实提示
    var preds = wx.getStorageSync('predictions') || {};
    delete preds[id];
    wx.setStorageSync('predictions', preds);
    wx.showToast({ title: '已开球，封存被拒', icon: 'none' });
    that.refreshCards(); // 或对应刷新
    return;
  }
  // true / false 均视为本地已生效（false=断网降级，本地判据自守）
});
```
注意批量封存（onSeal）需收集 rejected 的 id 列表统一回滚并提示 N 场被拒。

### P1-4：me.js 判据双标（双路共见）
**方案**：抽公共函数（伪码）：
```javascript
function eachValidPred(cb) { // 封存校验+迟到作废 统一入口
  var preds = wx.getStorageSync('predictions') || {};
  Object.keys(preds).forEach(function (mid) {
    var p = preds[mid], m = data.getMatch(mid);
    if (!m || !p || !crypt.verify(p)) return;
    var kickTs = engine.ts(m.t);
    if (p.ts && !isNaN(kickTs) && p.ts > kickTs + 60000) return;
    cb(p, m);
  });
}
// 命中率与 seasonPts 两个循环都改走它，一处判据两处消费
```

### P1-5：tbd 占位时间当真（1191/1753 场）
tbd 场次的 `t` 是导出时的占位时间，`detail.js checkPred/onSealSingle` 用它判 closed：真实开球提前→赛后仍可封存；推后→提前误封门。seal 服务端兜底用的 fixtures.t 与占位时间相同，同样失效。

**方案**：**tbd 场次隐藏盲评面板**（最干净）——detail 页 `wx:if="{{!m.tbd}}"` 包住预测区，predict 页竞猜单已过滤 tbd（`!m.tbd` 已存在）核实无遗漏；同时在 onSealSingle 入口加 `if (raw.tbd) { toast('时间未定，暂不可预测'); return; }` 双保险。数据侧等 ESPN 确定时间后 syncScores 自然修正。

### P1-6：quips.json 损坏
[export_cloud_data.js L43-57](file:///tools/export_cloud_data.js#L43-L57) 对纯字符串 `Object.assign({}, item)` → 每句变 `{"0":"熬",...}`。当前云函数未读 quips 无运行时影响，但导入即坏数据。
**方案**：导出脚本 `typeof item === 'string' ? { text: item } : item`；本地 cloud_data/quips.json 重导出（或直接删除该文件——云函数根本不消费 quips，本地 data/quips.js 才是数据源，可考虑从 cloud_data 移除）。

### P1-7：poster.js 画布失败死锁
`initCanvas` 的 exec 回调 `if (!res || !res[0]) return;` 不调 cb → save() 的 loading 永挂、`_saving` 永真、按钮永久失效。
**方案**：
```javascript
.exec(function (res) {
  if (!res || !res[0]) { cb(new Error('canvas node not found')); return; } // 失败也回调
  ...
});
// save() 里：this.initCanvas(function (err) { if (err || !that._canvas) { done(); toast(...); return; } run(); });
// draw 的 _loadLogos Promise.all 加 10s 超时兜底（Promise.race）
```

### P1-8：分享冷启动死胡同
detail/poster/story 三页无效 id → `setTimeout(navigateBack, 800)`。从群分享冷启动时页面栈仅 1 层，navigateBack 静默失败 → 白屏卡死。跨赛季 id 失效是真实场景。
**方案**（三处同款）：
```javascript
setTimeout(function () {
  if (getCurrentPages().length <= 1) wx.switchTab({ url: '/pages/today/today' });
  else wx.navigateBack();
}, 800);
```

### P1-9：海报标语「明晨」错配（本地独有）
[poster.js L19-21](file:///miniprogram/pages/poster/poster.js#L19-L21)：周五 22:00 为周六 03:00 场生成海报，dayLabel='明晨' → 标语「**明晚**哪场值得熬」。但该场 5 小时后开球、属今晚熬夜。
**方案**：`'明晨'` 归入今晚分支：`(dayLabel === '今天' || dayLabel === '今天凌晨' || dayLabel === '明晨') ? '今晚哪场值得熬' : ...`（明晨=今晚熬到天亮，语义同今晚；「明天」才用明晚）。

### P1-10：pushReminders 一次性订阅语义（双路共见）
`status:'accept'` 被当长期有效，实际微信一次授权只推一条，耗尽后静默失败、每次触发重试浪费调用。
**方案**：发送成功后 `update({ data: { status: 'consumed', usedTs: Date.now() } })`；查询条件保持 `status:'accept'`；发送失败且 errMsg 含 43101（用户已拒收）也标 consumed。subscriptions 集合加 `(status, uid)` 索引。
