## 一、创建数据库集合（10 个）

云开发控制台 → 数据库 → 新建集合，逐个创建：

| 集合名 | 权限 | 说明 |
|---|---|---|
| `fixtures` | 所有用户可读，仅创建者可写 | 赛程（服务端写入，客户端只读） |
| `recommendations` | 所有用户可读，仅创建者可写 | 推荐看点 |
| `storylines` | 所有用户可读，仅创建者可写 | 故事线 |
| `predictions` | **仅创建者可读写** | 盲评猜球（防偷看的根基：只能写自己的，看不到别人的） |
| `checkins` | **仅创建者可读写** | 夜猫打卡 |
| `boasts` | **仅创建者可读写** | 德比法庭留言 |
| `users` | 仅创建者可读写 | 用户昵称与偏好；**等级/积分由 settleMatches 云函数独占写入，客户端经 readBoard profile 只读** |
| `subscriptions` | **仅创建者可读写** | 订阅消息授权记录（pushReminders 用） |
| `standings` | 所有用户可读，仅创建者可写 | 赛季总榜（云函数写入） |
| `weeklyReports` | 所有用户可读，仅创建者可写 | 周报快照 |

**关键**：predictions / checkins / boasts 三个集合必须设为「仅创建者可读写」——这是防偷看的根基，用户只能写自己的数据，看不到别人的，排行榜必须走云函数中转。

## 二、部署云函数（7 个）

微信开发者工具 → 右键 `cloudfunctions/` 目录下每个文件夹 → 「上传并部署：云端安装依赖」

按顺序部署（标 🔁 者为本轮四轮审查修复改动，已部署过也需重新上传）：

1. `seal` 🔁 —— 玩法写入收口（服务端时间戳 + openid 归属 + (uid,场次) 唯一性 + 哈希前置校验；互动反应幅度已封顶 1~3；不再接受客户端写等级/积分）
2. `settleMatches` 🔁 —— 比分结算（每小时定时）；修复 hitCount 恒 0，users 等级/积分改为跨 gid 汇总后按 uid 只写一次
3. `readBoard` 🔁 —— 榜单读取；**新增 `board:'profile'` 分支**（服务端取 OPENID 精确读本人 users 档案，me 页依赖）
4. `weeklyReport` —— 周报生成（含定时触发器）
5. `pushReminders` —— 开球提醒（含定时触发器）
6. `syncScores` 🔁 —— ESPN 比分自动同步（每 15 分钟定时）+ manual 管理员补录；**manual 白名单已恢复「空 = 拒绝所有人」安全默认态**，比分修正会先回滚旧结算再重结
7. `checkCrests` —— 队徽云存储存活性诊断（可选，不参与业务链路）

部署后控制台会显示「上传成功」。定时触发器在 `config.json` 里已配好，部署时自动生效。

> `seal` 未部署时客户端自动降级集合直写（M2 本地体验不受影响），正式运营前必须部署。

> `pushReminders` 部署后需在控制台「云函数 → 配置 → 环境变量」补充：
> - `TMPL_KICKOFF`（开球提醒订阅消息模板 ID）
> - `TMPL_DEADLINE`（盲评截止提醒订阅消息模板 ID）
>
> 模板未过审前保持未配置即可——函数会安全空转，客户端已走 ICS 日历导出兜底。

> **`syncScores` 管理员补录开关（manual 分支）**：白名单硬编码在源码中，不走环境变量
> （微信云函数自定义环境变量下发不可靠，空名单 = 拒绝所有人是刻意保持的安全默认态，四轮 P0-1）。
> 需要手动补录比分时：
> 1. 获取自己的开发者 openid：云开发控制台 → 「用户管理」，或临时在 seal 日志里打印 `wxCtx.OPENID`；
> 2. 编辑 `cloudfunctions/syncScores/index.js` 顶部 `const ADMIN_OPENIDS = []` 填入该 openid；
> 3. 重新部署 `syncScores`。补录入口：控制台 → 云函数 → syncScores → 测试，传 `{ "manual": { "id": "场次id", "score": "2-1" } }`。
> 4. 补录已完赛且已结算的场次时会自动回滚旧积分再按新比分重结，无需人工善后。

## 四、验证（部署后自测）

1. 控制台 → 云函数 → `settleMatches` → 测试 → 传空参数 `{}` 运行
   - 期望返回 `{ ok: true, matches: N, predictions: 0, void: 0, standings: 0 }`（N = 云库当前已完赛未结算场次数；再次运行变成 `matches: 0`，因已标记 settled）；`predictions: 0` = 暂无用户预测，空转正常
   - 注：settleMatches 已配置每小时定时触发（`config.json`），日常无需手动运行
2. 控制台 → 云函数 → `readBoard` → 测试 → 传 `{ "board": "owl", "gid": "test" }`
   - 期望返回 `{ ok: true, board: "owl", list: [], worst: null }`
3. 控制台 → 云函数 → `weeklyReport` → 测试 → 传空参数 `{}`
   - 期望返回 `{ ok: true, week: "2026-08-10", groups: 0, cards: [] }`
4. 控制台 → 云函数 → `seal` → 测试 → 传空参数 `{}`
   - 期望返回 `{ ok: false, error: "action 必须是 prediction | checkin | boast | boast_reaction | judge | user" }`（参数校验生效即正常，注意文案已含新增 action）
5. 控制台 → 云函数 → `readBoard` → 测试 → 传 `{ "board": "profile" }`（四轮新增）
   - 控制台测试无登录态，期望返回 `{ ok: false, error: "no openid" }`
   - 真机打开「我的」页后，后端日志应能看到 profile 调用返回 `{ ok: true, profile: ... }`
6. 控制台 → 云函数 → `syncScores` → 测试 → 传 `{ "manual": { "id": "PD-2-RAY-ALA", "score": "1-0" } }`（鉴权回归验证）
   - 期望返回 `{ ok: false, error: "forbidden: admin only" }`（白名单为空 = 拒绝所有人；控制台测试无 OPENID 也会被拒）
7. 控制台 → 云函数 → `syncScores` → 测试 → 传空参数 `{}`
   - 期望返回 `{ ok: true, synced: N, updated: [...] }`；若云环境出网受限，`errors` 字段会列出各联赛失败原因，看日志定位即可（不影响其他链路）
