## 一、P0 · 防作弊链路三连洞（立即修复）

### P0-1：readBoard 封存判定布尔值完全反转

**位置**：`cloudfunctions/readBoard/index.js:112`

```javascript
const kt = m.t ? bjTs(m.t) : NaN;
const sealed = !(kt > now); // ⚠️ kt>now = 未开球；!(未开球) = 已开球 —— 变量实际持有"已开球"真值
```

**实证推演**：
- 未开球（`kt > now` = true）→ `sealed = false` → L125-127 下发 `pick / score / pts` **明文** → 任何人可抄作业、群内剧透；
- 已开球（`kt ≤ now`）→ `sealed = true` → 全部置 `null` → **赛后永远无法开箱对比**；
- 唯一正确的分支是 `kt = NaN`（场次未命中）：`NaN > now` = false → sealed = true → 保密（方向恰好对）。

外层总标记 L134 `sealed: ...some(e => e.pick === null)` 跟随同错。**这是 PM 八节权限规则「截止前只返回哈希」的直接违背。**

**修复**：
```javascript
const sealed = isNaN(kt) || kt > now; // 未开球或时间未知 → 封存保密；仅明确已开球才开箱
```

### P0-2：seal 业务拒绝 → 客户端降级直写，服务端校验被整体绕过

**位置**：`miniprogram/utils/cloud.js:53-61 + 94-99`

```javascript
function callSeal(payload) {
  ...
  if (res && res.ok === false) return false; // 业务拒绝（重复封存/哈希不符等）静默降级
  ...
}
// addPrediction：
return callSeal({...}).then(function (sealed) {
  return sealed ? true : add('predictions', doc);  // ⚠️ false → 无条件直写
});
```

**攻击链**（seal 已对 `kickoff passed` 做服务端时钟校验，全部被绕过）：
开球后请求 seal → 服务端拒绝（`kickoff passed`）→ 客户端把 `false` 当基础设施失败 → 直写 predictions（集合权限「仅创建者可读写」允许）→ 文档无 `sealTs` → settleMatches L92-94 回退 `ts + 60s` 客户端判据 → **伪造 ts 即可赛后骗分**。

**修复**（三态返回，业务拒绝不降级）：
```javascript
function callSeal(payload) {
  if (!available() || !wx.cloud.callFunction) return Promise.resolve(false);
  return wx.cloud.callFunction({ name: 'seal', data: payload }).then(function (r) {
    var res = r && r.result;
    if (res && res.ok === false) return 'rejected'; // 业务拒绝：云端已明确说不，禁止降级直写
    markUp();
    return true;
  }).catch(function () { return false; });           // 仅基础设施失败可降级
}
// addPrediction 调用处：
return callSeal({...}).then(function (sealed) {
  if (sealed === 'rejected') return 'rejected'; // 本地 storage 照存（本地判据自守），云端不入库
  return sealed ? true : add('predictions', doc);
});
```
`addCheckin / addBoast / syncUser` 调用处同步改为 `=== 'rejected'` 时跳过直写（调用方均为 fire-and-forget，返回值无消费方，改动安全）。

## 二、P1 · 确定性功能缺陷

### P1-1：pushReminders 订阅者字段错位 —— 推送链路静默失效

**位置**：`cloudfunctions/pushReminders/index.js:60-61` × `miniprogram/utils/cloud.js:157-159`

`saveSubscription` 走集合直写，文档无 `uid`（仅云库自动补 `_openid`）；云函数 `subMap[s.uid]` 键全为 `"undefined"`，`subMap[u.uid]` 恒空 → `if (!sub) continue` → **开球/截止提醒 100% 发不出**。次要缺陷：subMap 不分 `tmplId`，双模板授权互相覆盖。

**修复**：
```javascript
const subMap = {};
subs.forEach(s => {
  const uid = s.uid || s._openid || '';
  if (!uid) return;
  if (!subMap[uid]) subMap[uid] = s;
  if (s.tmplId) subMap[uid + '|' + s.tmplId] = s;
});
// 两处取用改为：
const sub = subMap[u.uid + '|' + TMPL] || subMap[u.uid];
```

### P1-2：decorate 展示日口径漂移（dayLabel/dateHeader/poster 标语）

**位置**：`miniprogram/utils/decorate.js:39-67`

`relDay` 基于日历日 `t.split('T')[0]`，未走 `engine.owlDay`（凌晨场归前一晚）。实证：8/21（周五）22:00 查看 8/22 03:00 场次 → 日历日 diff=1 → 「明天」；按夜猫口径 owlDay 归 8/21 → 应为「今晚」。连带 poster.js L17-20 标语漂移（注释声称已走夜猫口径，实现没有——**注释与实现不符，实锤**）。

⚠️ 澄清：报告A「境外时区算术漂移」子论点**不成立**——relDay 两侧均本地时区解析、`Math.round` 容差 ±12h 足以吸收 DST 偏移，天数差不会错位。真实问题只有凌晨场归属。

**修复**：
```javascript
function relDay(t) {
  var mP = engine.owlDay(t).split('-').map(Number);
  var cP = engine.nightOf(Date.now()).split('-').map(Number);
  return Math.round((Date.UTC(mP[0], mP[1] - 1, mP[2]) - Date.UTC(cP[0], cP[1] - 1, cP[2])) / 86400000);
}
```
影响面：detail/predict/court/board/box/records/poster 七页的 dayLabel/dateHeader 统一切换 owlDay 口径（展示日期串保持日历日，语义「今天凌晨」由时间 HH:mm 自明）。修复后与 today/box/schedule 三页既有口径完全对齐。
