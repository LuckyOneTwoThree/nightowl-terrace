# 夜猫看台 · 项目架构详解（写给不看代码的人）

> 目标读者：没有代码基础的参与者（比如 Lucky 本人）。
> 读完你会知道：这个项目由哪几块组成、每块负责什么、数据怎么流动、改需求该找哪个文件。
> 专业的部分我会用比喻解释，比喻只求易懂，不求精确。

---

## 一、先说结论：整个项目像一家「深夜食堂」

| 食堂的部分 | 项目里对应的 | 作用 |
|---|---|---|
| 菜市场进原料 | `tools/`（抓取脚本） | 从 ESPN 把 1,753 场比赛数据抓回来 |
| 冷库与食材柜 | `miniprogram/data/`（数据层） | 存球队字典、赛程、看点文案等原材料 |
| 后厨的菜谱与厨师 | `miniprogram/utils/`（工具层） | 算出「今晚该熬哪场」的推荐引擎 |
| 前厅与餐桌 | `miniprogram/pages/`（页面层） | 用户看到的 15 个页面 |
| 传菜电梯 | `cloudfunctions/`（云函数，建设中） | 未来连接群友、排行榜、自动结算 |
| 装修设计图 | `stitch_night_owl_terrace_ui/` | 18 张视觉设计稿（Midnight Match 暗色风格） |
| 营业手册 | `pm/` | 产品设计方案（唯一权威 SSOT）+ 本文档 |

一句话记住架构：**数据从 ESPN 来 → 存在 data 目录 → 引擎在 utils 里计算 → 页面展示给用户 → 未来云函数负责群友互动。**

## 三、miniprogram/ —— 小程序本体

这是产品的全部「前台」。用户在微信里打开的每一个界面，都来自这里。

### 3.1 页面层：`miniprogram/pages/`（15 个页面）

微信小程序的每个页面由 4 个文件组成，命名完全相同、后缀不同：

| 后缀 | 比喻 | 职责 |
|---|---|---|
| `.wxml` | 房间的**骨架** | 页面上有哪些元素（文字、按钮、卡片） |
| `.wxss` | 房间的**装修** | 元素长什么样（颜色、大小、间距） |
| `.js` | 房间的**管家** | 元素的行为（点击后干嘛、数据怎么算） |
| `.json` | 房间的**门牌** | 页面标题等配置 |

15 个页面分两组：

**5 个主 Tab（底部导航栏）**

| 页面 | 品牌名 | 用户在这里干什么 |
|---|---|---|
| `today/` | 今晚之选 | 看「今晚该熬哪一场」的答案，3 秒决策 |
| `week/` | 本周预算 | 看本周最优看球组合、调额度、避雷 |
| `schedule/` | 赛程日历 | 按日期翻整个赛季 1,753 场比赛 |
| `play/` | 玩法大厅 | 猜球、打卡、法庭、盲盒的入口 |
| `me/` | 我的 | 关注球队、设置熬夜额度 |

**10 个子页面（从主 Tab 点进去）**

| 页面 | 干什么 |
|---|---|
| `detail/` | 单场比赛详情：倒计时、看点、添加日历提醒 |
| `predict/` | 盲评猜球：封存预测（加密防偷看） |
| `records/` | 预测/狂言/打卡的历史档案与结算 |
| `court/` | 德比法庭：赛前放狠话，赛后判应验还是翻车 |
| `board/` | 夜猫榜：凌晨看球打卡，统计肝度 |
| `box/` | 盲盒开球：随机抽一场今晚的比赛 |
| `story/` | 故事线详情：比如「名帅大迁徙」的时间轴 |
| `poster/` | 生成分享海报（1080×1920 图片） |
| `settings/` | 设置：额度、关注球队、清数据 |
| `onboarding/` | 首次使用的引导页 |

### 3.2 数据层：`miniprogram/data/`（7 个数据文件）

全部是 JSON 格式（可以理解为「格式严格的表格」）。这是产品的「原料库」。

| 文件 | 内容 | 谁维护 |
|---|---|---|
| `teams.json` | 96 支球队字典：三字码、中英文名、主色 | 建仓时定稿，基本不动 |
| `fixtures.full.json` | **1,753 场全量赛程**（五大联赛+德超杯） | 脚本自动生成，每周更新比分 |
| `fixtures.seed.json` | 早期种子数据 | 已被取代，仅留档 |
| `recommendations.seed.json` | 约 250-300 条**人工看点**：焦点战的三个看点、冷门预警 | 人工维护（赛季中的运营工作） |
| `storylines.json` | 12-18 条故事线：卫冕之路、名帅大迁徙等 | 人工维护，随剧情推进更新 |
| `rivalries.json` | 德比关系表：谁打谁是焦点 | 建仓时定稿 |
| `quips.json` | 夜猫絮语彩蛋文案 | 想加就加 |

**关键设计（PM 文档定的规矩）**：赛程层是机器生成的、**没有看点**；看点写在独立的推荐层。两层靠比赛 ID 关联。好处：更新赛程不会覆盖人工写的看点。

### 3.3 工具层：`miniprogram/utils/`（5 个核心模块）

这里是「大脑」，项目的核心算法全部集中于此。

| 文件 | 比喻 | 职责 |
|---|---|---|
| `engine.js`（299 行） | **主厨** | 推荐引擎：星级评定、夜猫指数计算、背包算法（预算内选最优组合）、雷区预警 |
| `data.js` | 传菜员 | 从数据层取数、缓存、提供查询函数 |
| `decorate.js` | 摆盘师 | 把引擎的生数据转成页面能直接显示的字段（比如把 `03:00` 变成「明天 03:00」+ 当地时间） |
| `crypt.js` | 封条机 | 盲猜的加密封存（SHA-256 哈希）：提交时盖封条，结算时验证封条没被换过 |
| `ics.js` | 日历信使 | 生成日历文件，让用户把比赛提醒导入手机日历 |

**核心公式（整个产品的灵魂，就一行）**：

```
夜猫指数 = (星级 × 10 + 故事线加成 0/5/10) ÷ (1 + 睡眠成本)
```

翻译成人话：比赛越精彩分子越高，熬夜越狠分母越大——**又好看又不用熬到吐的比赛，得分最高**。

**背包算法（本周页的「最优组合」）**：就像出差只能带 20kg 行李，从一堆想带的东西里挑出价值最高的一组。这里背包重量 = 熬夜额度，物品价值 = 夜猫指数。

### 3.4 全局文件

| 文件 | 作用 |
|---|---|
| `app.js` | 小程序启动时先跑的全局逻辑（读取你的设置、关注球队） |
| `app.json` | 全局配置：有哪些页面、Tab 栏怎么排 |
| `app.wxss` | 全局样式：颜色变量、卡片、按钮的统一定义（Midnight Match 暗色设计系统） |

## 四、tools/ —— 数据抓取工具（不上线的后台）

只在开发者的电脑上运行，用 Node.js 跑两个脚本：

| 脚本 | 职责 |
|---|---|
| `fetch_espn.js` | 从 ESPN 官方 API 按月抓比赛数据（用了 curl 绕开拦截的小技巧） |
| `build_fixtures.js` | 把抓到的数据「翻译」成我们的格式：英文队名→三字码、时区→北京时间、自动算熬夜档位（S0-S4） |

**运营节奏**：每周一重跑一遍这两个脚本，已踢完的比赛自动补上比分，全部分析自动更新。`tools/raw/` 存 ESPN 的原始返回，用于核对。

## 五、cloudfunctions/ —— 云函数（建设中，v1 关键）

**为什么需要它**：现在所有数据存在「你自己手机」的本地存储里——你的预测只有你自己看得见。要实现「群友一起玩、有排行榜」，数据必须放到云端，大家共读共写。

4 个云函数已完成编码（2026-08-18），等云环境开通后部署：

| 函数 | 触发时机 | 职责 |
|---|---|---|
| `settleMatches` | 比分补录后手动触发 | 自动结算预测：commit-reveal 哈希校验 → 胜平负 3 分、比分再 +2，写回总榜 |
| `readBoard` | 用户看榜单 | 按群返回盲评榜/夜猫榜/法庭/赛季榜，开球前只给哈希防偷看 |
| `weeklyReport` | 每周一 10:00（定时） | 生成周榜、最准之口、最狠一夜、法庭战报，快照落库 + 分享卡片数据 |
| `pushReminders` | 每 15 分钟（定时） | 开球提醒推送（模板未配时安全空转，ICS 日历兜底已上线） |

**已验证**：云端哈希算法与本地 `crypt.js` 十六进制结果完全一致（含中文/emoji 盐）；结算判据与本地 records 页逐例对齐；北京周界/开球时间换算全部通过 Node 断言。

**已埋好的伏笔**：本地加密模块 `crypt.js` 的算法与云端完全兼容——未来迁上云，防作弊逻辑不用重写。

## 七、一次完整的数据流动（以「今晚该熬哪场」为例)

```
① ESPN 服务器
   │  (tools/fetch_espn.js 每周抓取)
▼
② fixtures.full.json —— 今晚 03:00 阿森纳 vs 考文垂，S4 档
   │  (data.js 取数)
▼
③ engine.js —— 查推荐层：揭幕战有看点 ★★★；
   算指数：(3×10+10)÷(1+4) = 8.0；查雷区：不踩
   │  (decorate.js 摆盘)
▼
④ today 页面 —— 「今晚之选：阿森纳 vs 考文垂
   指数 8.0 · 熬夜 4h · 看点：卫冕冠军揭幕」
   │
▼
⑤ 你看到答案，3 秒做出决策：熬 / 睡
```

## 八、想改东西，该动哪里？（速查表）

| 你想改什么 | 动哪里 | 难度 |
|---|---|---|
| 某场比赛的看点文案 | `data/recommendations.seed.json` | 改文字即可 |
| 故事线剧情推进 | `data/storylines.json` | 改文字即可 |
| 彩蛋絮语加几句 | `data/quips.json` | 加一行即可 |
| 熬夜额度上下限 | `pages/week/week.js` 里的 12 和 1 | 改数字 |
| 推荐算法口味 | `utils/engine.js`（动前想清楚，判据必须可复算） | 需要开发 |
| 页面颜色/间距 | 对应页面的 `.wxss` | 需要开发 |
| 新增整块功能 | PM 文档先立项 → 再写代码 | 先讨论 |

**铁律**：任何改动，`pm/夜猫看台 · 产品设计方案（定稿）.md` 是唯一裁判。代码和文档不一致时，要么改代码，要么改文档并说明原因，不能装作没看见。
